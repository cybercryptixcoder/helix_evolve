# Brief, October 27, 2026 (09:12): a model of the search space, and what to build next

## The request

Shreyas shared a transcript of a discussion with a collaborator about the search space, plus written notes, and
asked for deep reasoning, research across fields (not only evolutionary algorithms), and a direction for the next
version. The thinking is in `docs/SEARCH_SPACE_MODEL.md`.

**The discussion, summarised** (the transcript itself is not reproduced here):
- A **feature** (a direction, an axis) is one aspect of a program that can be changed. A **point** on the map is a
  value for every feature; the score is the extra, vertical dimension. **Hills** are families of approaches: a
  combination of feature values gives each hill its top.
- Mutation today mostly **discovers new axes** (new directions to move from where we are). What is wanted as well
  is to **jump**: take the axes we have, give each a (random) value, land on that coordinate, and climb from there,
  hoping some landings are near taller hills than the one we are on.
- Discovering axes as we go means the space keeps growing, so searching all of it gets harder; but more axes also
  mean better solutions may exist in the same region. Existing programs are probably already somewhere on a new
  axis, because features overlap.
- The space is bounded in practice (programs that don't work are infeasible), like the interval between 1 and 2:
  infinitely many points, but a box.
- Machine learning randomises parameters to escape local optima. Here a point isn't quantified, so it can't be
  randomised yet: **how do we turn features into literal axes**, maybe discrete ones?
- The tree view (branching, backtracking) and the map view got mixed up: is every branch a feature, or a combination
  of features? Maybe the number of basic features is **fixed**, like primary colours, and everything else is a
  combination.
- One could cap the features (say 27), find the best within them, and expand only if it isn't enough; but capping
  can miss the best hill (an "addition only" search can't find a "swapping" solution).
- **Three steps agreed:** (1) find the features, and check whether their number is fixed; (2) make each feature
  modifiable, with values (possibly discrete); (3) combine values into coordinates and land on random points of the
  map.
