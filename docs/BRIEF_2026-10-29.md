### Agreed so far
1. **Standing rule:** state how things are implemented and any gap from what was asked (in `docs/REQUESTS.md`).
2. **An axis** is one simple thing a program does more or less of (a dial), or a switch. Tests: (a) independent: it
   can be changed alone; (b) it matters: changing it changes the result; (c) not a duplicate of another axis;
   (d) it has a trade-off: its best setting is not simply the maximum. Things where more is always better (steps,
   time) are **resources**, set once, not axes.
3. **Three kinds of thing:** resources (not axes); **ingredients** (the pieces approaches are built from, each with an
   amount: these are the axes); **approaches** (a recipe, i.e. a point: particular amounts of the ingredients).
   Knowledge becomes axes by taking each published approach apart into ingredients; shared ingredients are one axis.
4. **Concept to implementation (proposed):** a point is a setting of every axis, which is one runnable program; height
   is its score; a neighbour is one dial nudged a little; a hill is a region of settings that score well, rising to
   a peak; climbing is nudging dials the way the score rises; a jump is a far setting, then climb again.
5. **The project, in Shreyas's words:** search over ideas as a space rather than discover by chance; the model is a
   translator into code; the search is a stand-in for reasoning, and its traced path should read like reasoning.
6. **The dry-run problem:** circle packing (chosen 17:52).
