## 2. Notes and pointers

### Shreyas's hypothesis (to evaluate, not to accept)
- Every agent call (Researcher, Coder, Mutator...) is a **fresh instance**; the only context is "static": the
  champion's code, feature names and weights. No chain of earlier reasoning, so it can only write code "at that
  level", and that is (he suspects) why runs flatline. A single agent improving a program in one long conversation
  has continuity; the evolutionary setup doesn't.
- Fix idea 1: **append context** from earlier generations (what was tried, what was learned), managed somehow
  (chunking, compaction) since it can't grow forever.
- Fix idea 2: **a memory architecture** (from Avy): an immutable log, facts extracted with pointers to the log, a graph
  connecting related facts (with inferred facts), retrieval by walking the graph from a starting point. For Helix:
  a graph/tree of attempts (code branches, what worked, what failed, why), which the LLM can jump around in. A tree of
  code branches with what worked and failed on each; or graph nodes with trees attached; or something else.
- Progress records must be **informative**: not "branch C did 5% better" but "branch C changed X, which gained N
  because Y worked", useful to the next generation.
- **Open up the evaluator**: return more than a score (what worked, what didn't) without giving away the scoring;
  maybe an LLM in the evaluator commenting next to the score (he isn't sure that's a good idea).
- Known Avy problem: retrieval worked, but **message-to-message continuity** was poor. Check whether that applies
  here (this is progress-tracking, not conversation).
- Everything is **up for debate**: reason about what works, not just yes/no. Come back with "here's what we will
  build, how, and why it should work" (a discussion that ends in a decision, not a proposal document).
